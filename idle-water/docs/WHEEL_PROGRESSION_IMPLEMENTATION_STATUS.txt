INFINITE WATER — WHEEL PROGRESSION IMPLEMENTATION STATUS
==========================================================
Date: 21.08.2026
Branch: feature/wheel-progression

CURRENT VERIFIED GAME STATE
---------------------------
- Developer verified exactly one starting wheel is visible and rotating.
- Five Buy Wheel windows are visible.
- Windows are centered on their corresponding wheel tiles.
- Every window is intended to show exactly:
    Buy Wheel
    20$

CORE RULE
---------
The player may buy ANY of the five locked wheel positions at any time.
There is NO sequential purchase order.

A purchase window belongs to one specific wheel position. Clicking that window
attempts to purchase that exact wheel. The other four locked wheels remain
independently purchasable.

IMPLEMENTED
------------

PHASE 1 — DISCOVERY / CREATION SEPARATION
Status: COMPLETE

- Wheel marker positions are discovered before activation.
- Positions are converted to simulation coordinates and sorted deterministically.
- Maximum discovered wheel locations remains 6.
- Discovery does not instantiate all six wheel runtimes.

PHASE 2 — INITIAL ONE-WHEEL STATE
Status: COMPLETE

- A new game starts with exactly one wheel.
- The intended starting wheel is the third marker from the top.
- The other five wheel positions remain locked/inactive.
- Existing PBF simulation systems are not recreated.

PHASE 3 — DYNAMIC INDIVIDUAL WHEEL ACTIVATION
Status: IMPLEMENTED — RUNTIME TEST PENDING

WaterWheelManager now supports:
- IsWheelUnlocked(index)
- GetWheelPosition(index)
- ActivateWheel(index)
- TryUnlockWheel(index)

TryUnlockWheel(index) activates the exact requested wheel position. It does not
search for or require the next locked wheel.

Purchasing any wheel adds exactly one wheel to the existing running simulation.
It does not recreate the solver, particles, spatial hash, coordinator, existing
wheel states, rain, or existing energy.

PHASE 4 — ECONOMY
Status: IMPLEMENTED — RUNTIME TEST PENDING

- WheelPurchaseCost = $20.
- A purchase checks that the player has at least $20.
- $20 is deducted only after the requested wheel is successfully activated.
- Insufficient funds leave both wheel ownership and money unchanged.

PHASE 5 — FIVE INDEPENDENT BUY WINDOWS
Status: IMPLEMENTED — RUNTIME TEST PENDING

- Five small windows exist for the five locked wheel positions.
- Each window is centered directly on the corresponding wheel tile.
- Each window always displays:
    Buy Wheel
    20$
- Each window is an independent purchase target.
- There is no sequential-order restriction.
- Having $20 enables every still-locked wheel window, not just one specific window.
- Buying one wheel hides only that wheel's window.
- The remaining locked-wheel windows stay visible and independently clickable.

UI API
------
FluidSimulator now exposes:
- TryPurchaseWheel(int wheelIndex)

WheelPurchaseUi calls TryPurchaseWheel with the exact wheel index represented by
the clicked window.

LEGACY COMPATIBILITY
--------------------
TryUnlockNextWheel remains available for compatibility with older code, but the
new Buy Wheel UI does not use it. New gameplay/UI code should use
TryPurchaseWheel(index).

ENERGY TRACKING SAFETY
----------------------
When a wheel is activated, its previous-angle baseline is initialized to its
current angle so it does not create an artificial energy spike on purchase.
Existing wheel energy tracking is preserved.

PHASE 6 — PERSISTENCE
Status: NOT IMPLEMENTED

Wheel ownership is runtime-only. Persistence will be implemented later.

PHASE 7 — ENERGY VALIDATION
Status: IMPLEMENTED IN CODE / TEST PENDING

Runtime testing still needs to confirm that a newly purchased wheel generates
energy normally and existing wheels continue normally.

PHASE 8 — PERFORMANCE VALIDATION
Status: CODE SAFETY IMPLEMENTED / TEST PENDING

Purchasing a wheel adds only that wheel's colliders and visual. The simulation is
not rebuilt.

---------------------
